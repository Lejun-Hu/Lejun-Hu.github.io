> 过去十几年，GPU 几乎一直是“AI 算力”的代名词。尤其在 2012 年 AlexNet 使用 NVIDIA GTX 580 在 ImageNet 上取得突破之后，基于 CUDA 的 GPU 并行计算迅速成为深度学习的事实标准。从实验室里最早的一批 CNN 模型，到如今上千卡集群训练的大语言模型，绝大部分 AI 工作都建立在 GPU 生态之上。
>
> 但如果把视线再拉远一些，会发现这个格局正在逐渐变化。Google 早在 2015 年就已经在内部部署第一代 TPU，并于 2016 年正式公开这种专门面向 Tensor 运算的 ASIC 架构。随后 TPU v2 开始支持大规模训练，逐渐成为 Google 内部搜索、推荐与 Gemini、PaLM 等超大规模模型的重要基础设施。与此同时，Groq 等公司则进一步把“专用化”推向推理领域，提出了 LPU（Language Processing Unit）这一面向大语言模型推理的数据流架构。尤其在 2023 年之后，随着 LLM 推理延迟与 token throughput 成为新的瓶颈，LPU 开始逐渐进入大众视野。而 NVIDIA 自己也在不断把 GPU 做得越来越不像传统意义上的 GPU。Tensor Core、NVLink、NVSwitch、Transformer Engine 等设计，实际上都在让 GPU 越来越偏向专门为 AI workload 优化的数据流机器。
>
> 三者的演进，实际上指向同一个趋势：AI 计算正在从“通用并行处理器”逐步走向“为张量数据流高度定制化的专用计算系统”。
>
> GPU、TPU、LPU 恰好可以看作这条路线上的三个不同坐标。本文将从架构、内存系统、软件栈、互联扩展、硬件利用率以及设计思路几个维度，认真梳理它们之间的本质区别。

## 一、TPU、GPU、LPU 的架构差异

现代 NVIDIA GPU 的基本单元是流式多处理器（SM）。以 H100 为例，单芯片集成 132 个 SM，每个 SM 包含数十个 CUDA 核心、第四代 Tensor Core、特殊函数单元、寄存器堆以及一块可配置为共享内存或 L1 缓存的片上 SRAM。所有 SM 通过片上网络共享一个大的 L2 缓存，并经由内存控制器访问片外 HBM。这种架构的思想内核是"用海量线程隐藏访存延迟"：同一份 kernel 代码被实例化为成千上万个线程，硬件 warp scheduler 以 32 线程为单位进行 lockstep 调度，一旦某个 warp 在等待数据，调度器立刻切换至另一个就绪的 warp，从而保证执行单元不空转。正是这种设计，让 GPU 能够同时应对图形渲染、科学计算、视频编解码以及深度学习训练等截然不同的负载。

TPU 则完全是另一条路。Google TPU v5e 的计算核心是四个 MXU（Matrix Multiply Unit），每个 MXU 实质上是一个 128×128 的二维脉动阵列。在脉动阵列中，权重被预加载到每一个处理单元内，输入数据沿阵列方向流动，每个处理单元接收数据后与本地权重执行乘加运算，中间结果则沿另一个方向传递给下游单元继续累加。这种"权重静止、数据流动"的工作方式，最大限度地复用了从内存加载的数据，极大减少了片上数据搬运开销。TPU 没有 SM 那样的通用执行单元，也没有 warp scheduler，它对复杂控制流的支持十分有限，但其 dense tensor algebra 的吞吐效率远非通用架构可比。从 GPU 到 TPU，实质上是从"什么都能够做，而且做得不错"，走向"只做好一件事，但把它做到极致"。

Groq 的 LPU 则在这个方向上更进一步。LPU 从硅片定义阶段就只面向大语言模型推理，不支持训练。其架构是一种完全确定性的可编程流水线——编译完成后，每个时钟周期内数据在哪个位置、执行何种运算、经哪条路径流动，全部是已知且不可更改的。它不依赖传统的 cache hierarchy，不进行运行时动态调度，几乎已经可以被看作是一块专为 Transformer 推理设计的可编程 ASIC。

## 二、GPU 与 TPU 的内存系统差异

两套架构在内存子系统上的差异同样深刻，而且最能体现"运行时灵活性"与"编译时确定性"之间的取舍。

GPU 的内存层次是典型的自动缓存体系。数据从 HBM 被加载到 L2 缓存，再由每个 SM 内部的 L1 缓存或共享内存缓冲，最终送入寄存器供执行单元使用。硬件会自动合并连续地址的访存请求、将近期可能用到的数据保留在速度更快的存储器中，这一切对 kernel 开发者基本透明。这种设计的优势在于灵活性：无论计算图长什么样，GPU 都能尽力在运行时找到较好的数据搬运策略。但代价是，缓存命中率、prefetch 效果、内存带宽的实际利用情况都与 workload 特征高度相关，具有相当的不确定性。

TPU 的内存层次则采用三级显式管理，取消了自动缓存。最外层是 HBM，作为张量的主存储；中间是 VMEM（向量内存），通常是十几 MB 的片上 SRAM，速度远高于 HBM；最内层是寄存器，运算实际发生的地方。数据每一次从 HBM 到 VMEM、再到寄存器、写回的移动，都不是硬件自动完成的，而是由编译器在代码生成阶段插入精确的 DMA 指令。换言之，数据的搬运时机、tile 的大小、流水线的展开方式，全部在编译期就写死。XLA 编译器对整个计算图做全局规划，确保计算单元在需要数据时数据已经就位。这种做法把不确定性降到了最低，但也使 TPU 对动态形状、不规则计算格外敏感。

LPU 走得更远——它干脆用数百 MB 的片上 SRAM 直接存放模型权重，避免了 HBM 的访问延迟。SRAM 的访问速度约为 HBM 的 20 倍，这意味着流水线可以全速运转，几乎不存在等待权重数据的问题。

## 三、GPU 与 TPU 的软件栈差异

单看硬件指标容易忽略一个事实：AI 芯片最终比拼的不是理论 FLOPS，而是实际能稳定跑出来的有效算力。这一点上，软件栈的差异至关重要。

GPU 的软件生态以 CUDA 为核心。开发者用 C/C++ 扩展语法编写 kernel，编译器生成 PTX 中间码，GPU 驱动在运行时进一步编译为机器码。在这一流程中，NVIDIA 的编译器会执行图优化、算子融合、访存合并等操作，但具体到某个 kernel 在某颗芯片上的执行时序，仍由硬件 warp scheduler 动态决定。哪个 warp 在哪个时刻被发射到哪些执行单元，取决于运行时的资源可用性和数据就绪状态。这种设计使得同一套 CUDA 程序可以在不同代际、不同规模的 GPU 上直接运行，灵活性极高。但它的另一面是，kernel launch 开销、stream 同步、cache miss、warp divergence 等都会造成实际效率与理论峰值之间的落差。要把一块 GPU 用满，往往需要反复 profiling 和手工调优。

TPU 的软件栈建立在 JAX 和 XLA 编译器之上，采用编译期确定性策略。用户用 Python 写出的 JAX 代码被 trace 为中间表示，XLA 编译器对整个计算图进行全局分析，完成算子融合、内存分配规划、DMA 传输调度，甚至连 collective communication 的时机和模式都在编译阶段确定下来。编译完成后，TPU 上的执行路径是 100% 确定的，不存在运行时调度器临时决策的空间。这种做法带来两个直接后果。一是效率极高：流水线容易保持满载，数据搬运与计算可以精确 overlap，硬件利用率远超通用平台。二是编程约束很强：JAX 要求函数是纯函数，动态控制流和条件分支的表达能力受限，许多在 GPU 上自然而然写出来的逻辑，在 TPU 上需要围绕静态数据流重新组织。

LPU 的软件设计从一开始就是模型无关的——编译器直接读取模型描述，生成精确到时钟周期的执行计划，不需要为每一个新模型手写 kernel。这种"软件定义硬件"的思路，将灵活性的边界从运行时彻底前移到了编译时。

## 四、GPU 与 TPU 的互联与扩展能力差异

大模型训练真正困难的部分，已经不是单颗芯片的算力，而是多芯片之间如何高效通信。在这一点上，GPU 和 TPU 选择了截然不同的技术路线。

GPU 的互联分为机内和机间两个层级，使用完全不同的协议和硬件。机内互联依靠 NVLink 和 NVSwitch。第五代 NVLink 为每颗 Blackwell GPU 提供 1.8 TB/s 的双向带宽，NVSwitch 作为无阻塞交叉开关，可将最多 576 颗 GPU 连接在一个全互联域内，聚合带宽超过 1 PB/s。第三代 NVSwitch 还内置了硬件多播与网内归约（SHARP）加速，能在交换芯片内部直接完成 all-reduce。机间互联则依赖 InfiniBand 或以太网，通过胖树拓扑和 RDMA 实现跨节点通信。需要指出的是，NVLink 与 InfiniBand 之间存在显著的带宽落差——上一代 NVLink 单 GPU 双向带宽达 900 GB/s，而同时期 HDR InfiniBand 的二分带宽仅为前者的约九分之一。此外，真实负载下 NVLink 的有效带宽往往低于标称峰值，通信模式、拓扑距离、内存带宽竞争和软件栈开销都会造成损耗。

TPU 则在 scale-up 和 scale-out 两个层级使用统一的 ICI（Interchip Interconnect）协议，仅物理介质有所不同。TPU v7 在机柜内采用 3D Torus 拓扑，每颗芯片在三维空间中与六个方向的近邻直接连接；跨机柜则通过 OCS（光学电路交换）组成扁平化高基数网络。这种设计使 TPU 的物理拓扑可以尽可能贴近张量分片和 collective communication 的模式。规模上看，单一个 Virgo 网络即可容纳 13.4 万颗 TPU，借助 Jupiter 数据中心网络和 Pathways 框架，可进一步扩展至百万颗芯片级别。Anthropic 已公开宣布将部署超过一百万颗 TPU 来训练未来的 Claude 模型。TPU 在扩展性上的最大特点并非单纯"能连得更多"，而是拓扑、通信模式与计算数据流之间的协同设计，使得跨芯片通信开销的上升曲线比传统分布式集群更为平缓。

## 五、GPU 与 TPU 的利用率差异

理论峰值算力是一个容易被放大讨论的数字，但对实际使用者来说，真正重要的指标是模型 FLOP 利用率（MFU），即有多少理论算力最终稳定地用在了矩阵乘法和注意力计算上。

GPU 在这一点上长期面临挑战。大规模训练中，相当一部分算力实际上被通信等待、同步屏障、kernel launch 延迟、数据加载流水线断流以及运行时调度不确定性所消耗。行业内公开的经验是，经过深度优化的 GPU 集群能够将 MFU 稳定在 30% 到 50% 之间，便已属相当不错的成绩。即使是机内 NVLink 带宽，研究也发现其实际利用率因流量偏斜、路径不均衡和 NCCL 路由低效等因素，经常未能跑满标称峰值。

TPU 因为其编译期完全确定性的数据流设计，在大规模矩阵运算中天然具备利用率的优势。流水线预排、通信与计算的重叠、算子融合等均提前规划好，runtime jitter 被压缩到极低。JAX 社区与 Google 公开的技术资料显示，TPU 在典型训练负载上能够达到 60%–70% 以上的 MFU，部分内部大模型训练案例中，整个 TPU Pod 的硬件利用率甚至超过 90%。对于拥有成千上万颗芯片的超大规模集群而言，"少一点运行时混乱"往往比"多一点理论 FLOPS"更具实际意义。当然，这种高利用率的前提是 workload 必须足够规整——一旦计算图中出现大量动态 shape 或复杂控制流，静态编译的优势就会显著降低。

LPU 则把利用率问题推到了最极端：编译器对全局执行路径的绝对掌控，使得硬件在推理过程中几乎没有空闲周期，能效比可达 GPU 的 10 倍。

## 六、GPU、TPU 与 LPU 的设计思路差异

如果跳出技术参数，从更宏观的层面审视这三种硬件，会发现它们反映的是完全不同的工程哲学。

GPU 的成功，本质上是平台化的成功。它最初并非为 AI 而生，CUDA 将其从一个图形硬件扩展为通用并行计算平台。这意味着它天然拥有庞大的开发者基础、成熟的工具链以及覆盖游戏、渲染、HPC、AI 等众多领域的软件生态。当深度学习浪潮来临时，GPU 能够迅速承接，并通过逐代增加 Tensor Core、强化互联、发展 NCCL 和 TensorRT 等方式不断向 AI 靠拢。它的核心优势是通用、上手门槛低、社区庞大，对多种 workload 兼容性强。一个本科生用一张消费级显卡就能跑起小模型，而同一套代码也可以几乎不加修改地部署到千卡集群。这种从游戏市场自然生长出来的生态位，是其他任何专用硬件都难以复制的。

TPU 则体现了一种完全不同的系统思维。它由 Google 从自身大规模 AI 任务的需求出发，从零开始重新设计，强调编译器、数据流、系统整体优化和基础设施的协同。TPU 不是"更好用的 GPU"，它是 Google 为其内部训练与推理链路量身打造的一台超大规模矩阵计算机。这种设计与 Google 其他经典基础设施作品——如 Kubernetes 对容器编排的系统化抽象、Chromium 的多进程安全架构——在底层逻辑上是相通的：将复杂性从用户端转移到基础设施端，用系统级设计换取上层简洁性与可控性。TPU 在单位算力能耗、系统利用率和超大规模训练效率上做到了极为出色的水平，但它对技术栈的绑定、对静态数据流的要求，也使得它天然更适合拥有强技术团队和固定训练管线的组织。

LPU 代表了最远端的专用化：为单一场景（大语言模型推理）从硅片定义阶段就全部打通的定制设备。它牺牲了几乎所有通用性，换取了确定性和延迟上的极致表现。这种设计目前在生态成熟度和适用广度上远不及前两者，但它划出了"专用架构可以走多远"的边界，也在倒逼行业重新思考：当负载足够大、足够集中时，是否还值得为用不上的灵活性付出功耗和面积代价。

## 结语

GPU、TPU、LPU 并非简单的迭代替代关系，而是 AI 时代计算架构重新分化的产物。GPU 在通用并行计算平台的位置上不断吸收专用计算能力，TPU 在矩阵数据流机器的轨道上追求编译期确定性和超大规模效率，LPU 则将推理流水线的固定化推向极致。而 NVIDIA 的下一代设计也在逐渐向更规则的数据流和更紧密的互联拓扑靠拢，TPU 则在不断提高对动态特性的支持，专用与通用之间的边界正在变得模糊。未来 AI 基础设施竞争的核心，已经不是谁的理论算力更高，而是谁能让整个系统的数据流、内存、互联与计算协同运转得更高效。而这，或许才是接下来十年真正的决定性变量。
